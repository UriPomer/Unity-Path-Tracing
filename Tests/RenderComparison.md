# ReSTIR 场景对照

## 先验合同与失败情形

同一场景、相机、路径深度和材质模型下，PT、DI、GI、DI+GI 应估计同一个线性 HDR 图像。ReSTIR 改变方差和相关性，不改变收敛期望。判断依据是跨独立种子的区域均值及误差，不以日志通过、最大亮度阈值或单张噪声图判定无偏。

修复前需要区分以下失败：

- 根据本次抽到的二次材质启停 GI，导致积分域由随机结果决定；混合漫反射和光滑材质时均值偏移。
- 初始采样与 reservoir 替换重用相同随机数，破坏条件选择概率；DI 单独开启即可改变亮度。
- 复用归一化计入原接收点无法采样到的遮挡路径或背面路径，导致暗边、漏光或持续亮点。
- 常规路径在二次反弹沿用主像素的光源裁剪列表，与 GI 使用的完整光源域不一致。
- 流式累积权重、最终贡献乘数和样本数量混用；零样本被丢弃、样本上限改变亮度。
- 相机、材质、光源或分辨率变动后，积累和 history 没有一致失效；组件停用再启用后资源未重建。
- 非均匀缩放或光滑法线被错误当作几何法线，改变求交结果或面积 Jacobian。
- 淡出透明在求交时随机跳过，阴影、GI 的连接支持与 BSDF 概率不一致；半透明遮挡应输出解析透射能量。
- GPU 输出非有限值、帧数被不断复位、渲染挂起或实际模式与要求不一致。

## 重复运行

输出开关回归：在下述命令添加 `-renderCheckAccumulation true`，使用真实场景、`Camera.Render` 和 DI+GI 渲染执行开→关→开，每次四帧。逐像素检查开启时等于独立读回的帧均值、关闭时等于当前帧，以及切换后的历史清空和 `Frame Limit` 冻结输出。保存 `accumulation-check.json` 与三张线性 EXR；开关缺失、始终开启、旧样本残留或冻结分支错误均应失败。普通估计量对照显式开启累积，避免旧场景设置改变比较口径。

在包含当前 Assets、Packages、ProjectSettings 的独立工程副本中，使用工程指定的 Unity 6000.4.4f1：

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.4.4f1\Editor\Unity.exe' -batchmode -force-d3d11 -projectPath '<工程副本>' -executeMethod ReSTIRRenderComparison.Run -renderScene Assets/Scenes/CornellBox.unity -renderFrames 2048 -renderRepeats 8 -renderSize 128 -renderOutput '<输出绝对路径>' -renderRevision '<本次源码标识>' -logFile '<输出绝对路径>\unity.log'
```

运行经过 Play 模式、真实场景、Camera.Render、生产 C# 调度及 Compute Shader；禁用相机移动和自动相机渲染，固定分辨率并手动渲染准确帧数。每个模式和种子重新开始积累及 history。场景改动不保存。

产物包含每次运行的 EXR、从下往上排列的小端 RGBA float32 原始图像、使用相同显示曲线的 PNG，以及记录环境、种子、模式、样本数和命令的 manifest.json。时间包含 CPU 提交与最终 GPU 读回，不能当作纯 GPU 帧时间。高亮点和相关样本需要足够重复次数；统计相容仅支持本场景范围内的结论。

## 解析场景与统计检查

`-renderScene` 可用 `analytic`、`mixed`、`alpha` 或 `glass`，也可用实际场景路径。这些解析场景由入口临时构建：

|场景|设置|线性亮度期望|
|---|---|---:|
|analytic|反照率 0.5 的 Lambert 平面，单位恒定环境|0.5|
|mixed|同一平面，上方半边为单位发光的黑色光滑金属，其余为单位环境|0.5|
|alpha|同一平面，单位垂直方向光，单层 alpha 0.5 遮挡，无环境|0.25 / π|
|glass|理想透明平板，IOR 1.5，单位环境，路径深度 8|约 1（遗漏的高阶内部反射远小于统计误差）|

每个场景依次运行 PT、DI、GI、DI+GI 和停用再启用组件后的 PT。`gpuBufferBytes` 记录相机实际分配的计算缓冲字节数；`materialSnapshot` 记录实际上传材质，防止测试输入与描述不一致。独立 Editor 内部错误单列在 `editorErrors`；渲染器错误、GPU 非有限输出或未完成帧数使运行失败。

```powershell
python Tests/Compare-ReSTIRRenders.py '<输出绝对路径>'
```

分析脚本需要 NumPy，读取原始浮点产物，生成 `analysis.json` 和 `analysis.md`。检查全图及 4×4 区域均值，按跨独立种子的差值标准误计算 5 倍标准误加 1e-4 数值余量；重启用相同种子的逐像素误差检查。`PASS` 表示本次数据未发现超过阈值的差异，不能外推为任意场景的无偏证明。重尾噪声或可疑差异应增加独立重复和样本量，不能放宽阈值。

运行前在输出目录保存受影响的脚本、着色器、场景、包和项目设置的 SHA-256 清单，并将源码标识传入 `-renderRevision`。运行期间保持该工程副本不变。

## 优化的性能对照

性能比较前先冻结原始代码和输出，固定同一 GPU、场景、模式、分辨率、路径深度、种子与样本数。失败条件包括：改变样本数／深度以换速度、预热或图像编码计入稳定渲染时间、异步提交未等待 GPU 完成、同种子图像偏差、新增非有限值，以及另一负载显著退化。

`-renderWarmup 16 -renderBatch 64 -renderFrames 64` 每次捕获先执行 16 帧并同步 GPU，再清空积分／复用历史和重设种子。64 帧在同一次 Editor 回调内执行，计时结束于 HDR 读回完成，排除 EXR／PNG 编码与文件写入。`warmupSeconds` 单列预热耗时；`wallSeconds / frames` 是含 CPU、GPU 及最终读回的摊销成本，不是 GPU timestamp 或单帧显示延迟；不包含每帧 Editor Update、输入和其他相机的开销，不能直接换算成游戏帧率。至少五次重复，前后交错复验；原始和优化版都使用相同测量入口。

不改变估计量的优化优先要求同种子浮点图像一致；舍入改变需报告最大差和均方误差并复验多种子均值。不要把不同随机序列的单张差异直接判为偏差或用降低画质换得的速度当作等价优化。


优化版与原版同种子对照使用：

```powershell
python Tests/Compare-ReSTIRRenders.py '<优化版场景目录>' --baseline '<原版场景目录>'
```

此模式先检查设备、分辨率、样本数、种子数量、材质和预热设置相同，再报告完整计时样本、中位数、浮点 RGB 均方根误差、最大差及区域均值差。输出 `performance.json`；数值差异不合格时返回非零。性能收益需结合重复运行的分布判断，不能把一次中位数差自动判为可靠收益。

## CUDA 十四项方案的迁移结论

来源是本地知识库《CUDA 球体路径追踪的十四项优化》及 [Karim Sayed 原文](https://karimsayedre.github.io/RTIOW.html)。目标工程使用 Unity HLSL / D3D11、三角形 BLAS/TLAS 和 ReSTIR，以下按本工程的数据流判断，不引用作者的 CUDA 加速比作为验收值。

|Opt|本工程处理|收益条件与代价|
|---|---|---|
|1 热函数可见及内联|已有：各内核通过 include 看到 HLSL 函数体；保留|CUDA 跨编译单元问题不直接存在；不继续展开材质分支增加编译体积|
|2 显式栈|已有；实测后保留 64 槽栈|33 槽候选满足 BLAS 深度界且图像相同，但未证实稳定收益，且有较慢观测；跨轮计时也存在漂移，不能把全部变化归因于栈。保留原容量，未采集寄存器／spill 证据|
|3 缓存 AABB|已有构建时缓存；保留|对象变换后仍更新 TLAS，不通过跳过动态更新换速度|
|4 低权重硬截断|不采用|低 throughput 后仍可能命中高亮源；会破坏无偏要求|
|5 Russian Roulette|已有概率终止及幸存权重除以 p；保留|不降低深度、不提高死亡率以换取有噪声代价的速度|
|6 连续数组与索引|已有；进一步延迟属性读取|每次 BLAS 查询只为最后命中计算完整材质与法线，裁剪材质仍在接受交点前检查 alpha|
|7 Slab 热循环精简|已有每 Ray 倒数；只去掉固定距离阴影查询的重复盒测试|最近命中查询保留缩短距离后的复检；未保留引起区域亮度偏移的激进候选，也未引入 FMA 舍入变更|
|8 SAH|已有分桶 SAH；保留|不改变划分与树深度，不将静态场景特例推广为动态构建策略|
|9 16 字节对齐|实测后撤销|实验将 BLAS 排成两组 float3+int，TLAS 从 36 改为 48 字节；耗时无一致下降，不保留增大的工作集|
|10 Constant Memory|已有 HLSL 统一参数；保留|相机与帧参数按 shader 常量传递；不把大型按像素索引的数据搬入常量区|
|11 单精度 Intrinsic|已有 HLSL min/max 等内建函数；保留|没有 C++ 泛型推导到双精度的问题；未声称已经采集到 SASS 或消除了某条机器指令|
|12 轻量 RNG|已有单 uint 状态和分阶段种子；保留|不换成质量更低的序列，避免噪声结构和 reservoir 选择相关性变化|
|13 材质去分支|采用按查询职责裁剪计算|阴影只求覆盖率；不透明命中立即遮挡；无 normal map 不读 tangent。没有无条件计算全套玻璃／金属／漫反射再混合方向|
|14 GPU 共享输出|已有 RenderTexture 直接输出；进一步将队列清零留在 GPU|在现有生成 dispatch 清零，移除每帧 SetData；没有额外 dispatch、读回或改变同步顺序。性能捕获工具的读回不进入正常渲染|

本次没有新增优化开关或并存生产版本。实验候选只保存在被忽略的 `Tools/Output/cuda-opt-20260929/`，主路径保留通过对照的实现。

## 2026-09-29 实测结果

Unity 6000.4.4f1，RTX 5090，D3D11，512×512，每模式 64 spp，16 帧预热，7 个固定种子。下表单位为每样本摊销毫秒；正百分比表示耗时减少。两轮都分别测量修改前的工作树和最终优化路径，原始值没有按跨轮设备速度归一化。

|场景|模式|第一轮原版 → 优化|减少|第二轮原版 → 优化|减少|
|---|---|---:|---:|---:|---:|
|CornellBox|pt|0.635 → 0.585|+7.8%|0.779 → 0.727|+6.6%|
|CornellBox|di|0.798 → 0.783|+1.9%|0.957 → 0.979|-2.3%|
|CornellBox|gi|1.254 → 1.158|+7.7%|1.487 → 1.494|-0.4%|
|CornellBox|di_gi|1.405 → 1.251|+10.9%|1.616 → 1.574|+2.6%|
|Sponza|pt|4.844 → 4.355|+10.1%|5.878 → 5.238|+10.9%|
|Sponza|di|5.060 → 4.547|+10.1%|6.154 → 5.560|+9.6%|
|Sponza|gi|10.929 → 10.147|+7.2%|14.336 → 11.795|+17.7%|
|Sponza|di_gi|11.089 → 10.016|+9.7%|13.591 → 11.604|+14.6%|

Sponza 的 PT 两轮均减少约 10%，DI+GI 减少约 10%～15%。Cornell 部分模式的变化落在运行波动内，不能宣称全模式获益。不同进程轮次的绝对成本有明显漂移；这里报告原始两轮数据，不用作者的 CUDA 数字或单次最优结果替代。

前后保持相同像素数、路径深度、样本数、随机数流和缓冲布局。两个场景五种模式的同种子全图／4×4 区域均值差均通过检查；属性求值移动后有浮点图像差异，RGB RMSE 和最大差保存在 `performance.json`，没有声称逐像素完全一致或所有场景严格无偏。相机计算缓冲字节数未增加。本轮五个生产文件净减少 34 行，没有新增生产文件或优化开关。

原始 EXR／PNG／RGBA float32、两轮计时样本、实验失败候选、命令及前后源码快照保存在本地 `Tools/Output/cuda-opt-20260929/`；`baseline512` 对 `candidate` 是第一轮，`baseline-repeat` 对 `final-repeat` 是第二轮。源码基线包含此前尚未提交的 ReSTIR 修复，不能把全部收益归到更早的 Git HEAD。场景仅有用户原先的帧率上限差异，测量入口会统一设置帧率与手动渲染，提交保留该用户改动。

解析与材质回归全部通过（analytic / alpha / glass：512 spp × 8 种子；mixed：4096 spp × 16 种子）；组件重启同种子像素差为 0。既有 EditMode 检查 15/15 通过，严格日志夹具公式检查通过；未新增单元测试。
